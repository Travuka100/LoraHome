# LoraHome — LoRa-телеметрия температуры (Heltec WiFi LoRa 32 V3)

Система из двух плат **Heltec WiFi LoRa 32 V3** (ESP32-S3 + SX1262, 868 МГц):

| Роль | Прошивка | Питание | Особенности |
|---|---|---|---|
| **Передатчик** (sender) | `pio run -e sender` | блок питания | 2×DS18B20 на одной 1-Wire шине (GPIO4), показывает обе температуры на OLED, молча отвечает на запросы. Никаких кнопок/сна/батареи. |
| **Приёмник** (receiver) | `pio run -e receiver` | LiPo | Короткое нажатие — запрос телеметрии; на экране D1/D2, RSSI и **заряд батареи**; долгое нажатие (≥2 c) — **глубокий сон**; авто-сон после 60 c бездействия. |

## Проводка датчиков (передатчик, Heltec WiFi LoRa 32 V3)

Оба DS18B20 висят на **одной** шине 1-Wire — различаются по ROM-адресу,
порядок на экране = порядок адресов на шине:

```
VCC(3V3) ──┬── DQ датчика 1 ──┬── DQ датчика 2 ──── GPIO4 + подтяжка 4.7кОм к 3V3
GND ───────┴── GND датчика 1 ─┴── GND датчика 2
```

| Pin платы Heltec V3 | Куда |
|---|---|
| `3V3` | красный (VDD) обоих DS18B20 + один вывод подтяжки 4.7 кОм |
| `GPIO4` | жёлтый/сигнал (DQ) обоих датчиков + второй вывод подтяжки 4.7 кОм |
| `GND` | чёрный (GND) обоих датчиков |

## Протокол (`lib/LoraHome/LoraHomeProtocol.h`)

Фиксированный кадр 16 байт, little-endian:

```
magic | version | from | to | type | seq | temp1(x100) | temp2(x100)
      | battery_mv | flags | reserved | crc16(XMODES)
```

* `REQUEST (1)` приёмник → передатчик; `RESPONSE (2)` передатчик → приёмник,
  **echo `seq`** = подтверждение (ACK уровня приложения).
* temp = `0xFFFF` + снятый флаг канала → «датчика нет/ошибка».

### Защита от ошибок (многоуровневая)

1. **CRC на уровне радио** (SX1262 hardware CRC) — мусор отсеивается PHY.
2. **CRC-16/XMODES в кадре** — второй контур проверки.
3. **Magic + версия протокола** — чужие/старые прошивки игнорируются.
4. **Адресация from/to + тип пакета** — пакет «не нам» не обрабатывается.
5. **Детектор дубликатов**: приёмник при ретраях инкрементирует `seq`;
   передатчик на одинаковый `seq` в окне 4 c отвечает один раз.
6. **Таймауты везде**: ожидание TX_DONE/RX_DONE ограничено, вечных блокировок нет.
7. **Ретрансляции**: до 3 попыток запроса со случайным backoff; неудача —
   понятное сообщение на экране, а не зависание.
8. **Датчики**: значение вне паспорта DS18B20 (−55…+125 °C, −127/NaN) → канал
   помечается невалидным, второй датчик и связь продолжают работать.
9. **Кнопка**: аппаратный debounce 30 мс, раздельные события SHORT/LONG;
   после пробуждения — guard-окно против ложных нажатий в кармане.
10. **Батарея**: trimmed-mean из 9 выборок ADC (GPIO35, делитель 220k/100k = ×3.2)
    + кусочно-линейная LiPo-кривая.

## Исправленные проблемы прошивки (v0.3)

| Симптом | Причина | Исправление |
|---|---|---|
| Долгая отправка / ожидание ответа | SF12 (~1.5 с эфирного времени на кадр) + таймаут ответа 8 с × 3 попытки | PHY SF9 (≈0.4 с/кадр), таймаут 1.5 с, 4 быстрые попытки; типовой раунд ≈1 с |
| Батарея всегда 0 % | ADC читался с GPIO37 (на V3 «прижат» цепью антенного switch-ера) и с коэффициентом V2 (2.34) | Чтение с GPIO35 (ADC1_CH7), корректный делитель V3 ×3.2 |
| Передатчик не отвечает | Не настроены DIO2-as-RF-switch и TCXO (DIO3) — у Heltec V3 без них передатчик радио фактически «нем»; плюс гонка: RX_DONE латчится в регистре радио, пока MCU занят, а код ждал только нового фронта DIO1 | `setDio2AsRfSwitch(true)` + `setTCXO(3.4f)` до `begin()`; быстрый опрос залаченного `getIrqStatus()` перед ожиданием фронта |

## Архитектура

```
src/
  common.h/.cpp   общий слой: OLED (дедуп редрав), radio init, IRQ-wait,
                  poll/take валидированного приёма
  sender.cpp      роль передатчика (setup/loop)
  receiver.cpp    роль приёмника (FSM: IDLE -> запрос -> результат/ошибка, сон)
lib/
  Board/          пины Heltec V3, Button (debounce/short/long), radioBegin,
                  батарея (мВ/%), deep sleep (radio.sleep + VEXT off + EXT0 wake)
  Sensors/        корректная обёртка 2×DS18B20 (исправлен висячий указатель
                  старой lib/DS18B20: OneWire теперь живёт внутри объекта)
  LoraHome/       протокол (структура кадра, CRC, encode/parse)
```

LoRa PHY (одинаков на обеих платах): **868.7 МГц, BW 125 кГц, SF9, CR 4/5, +20 dBm**.

## Сборка и прошивка

```bash
pio run -e sender   -t upload   # плата-передатчик
pio run -e receiver -t upload   # плата-приёмник
```

Режим выбирается окружением сборки — никаких `#define MASTER_MODE` в коде.

> Примечание: коэффициент делителя батареи (`BAT_DIVIDER`, `lib/Board/Board.h`)
> откалибруйте мультиметром под конкретную ревизию платы.
